Regime classifier preview: current vs proposed

Every cached session re-classified under the proposed rule — net conviction instead of two separate occupancy thresholds, side-changes instead of raw quadrant flips, and a net-travel gate that splits real trends from gap-and-park days. Nothing here is written back; this is a dry run over the existing v5 artifacts.

Where the days land

The current rule files over half of all days as mixed. The proposed rule re-reads most of them: strongly one-sided days blocked only by shallow churn become trends, and one-sided days that never travelled become parked — a class the current rule can't see.

The two rules

Current — classify()

  1. trend_up if abr ≥ 0.7 and transitions ≤ 2/hr
  2. trend_down if bbr ≥ 0.7 and transitions ≤ 2/hr
  3. balance if abr < 0.6 and bbr < 0.6 and ny vwap crosses ≥ 2/hr
  4. mixed otherwise
The transitions gate counts every quadrant flip — including shallow dips through one anchor that never change sides. 63 of the 97 mixed days were one-sided days blocked by that gate; 43 of them changed sides at most once an hour.

Proposed

  1. net conviction nc = abr − bbr; deep flips = side changes only (above-both ↔ below-both); net travel ntr = (close − open) ÷ range
  2. trend_up / trend_down if |nc| ≥ 0.5 and deep flips ≤ 1.5/hr and |ntr| ≥ 0.3
  3. parked if one-sided as above but |ntr| < 0.3 — held one side of both anchors yet went nowhere
  4. balance if |nc| < 0.3 and (vwap crosses ≥ 2/hr or deep flips ≥ 2/hr)
  5. mixed otherwise
One conviction number removes the [0.6, 0.7) dead zone. Deep flips come from the ribbon the artifact already stores; net travel needs one new KPI, calibrated on this data (trend days sit at 0.65+, parked days at 0.21 median).

Caveats. Thresholds (0.5 conviction, 1.5 deep flips, 0.3 travel) were calibrated on these same 173 sessions — treat them as a starting point, not a fit. The real acceptance test is whether the classes separate per-regime P&L better than the current ones; that join is the next step, not part of this preview.

Intraday stability is roughly unchanged (51% of days show their eod class by 12:00, vs 53% under the current rule) — a hard label is simply not knowable at noon, which is the argument for storing the class per checkpoint and the conviction score alongside it.
