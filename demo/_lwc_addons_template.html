Four lightweight-charts addons — on our tape

Every chart in the app is lightweight-charts with sixteen primitives we wrote ourselves. These four community packages cover ground we either built by hand or left unbuilt, and none of them had been pointed at real NQ data before this page. It renders from the tick cache through each one. The first four tabs each ask does it draw our data correctly; the fifth assembles all of it into the TradingView layout to see how much of that chrome the packages carry on their own.

Evaluation, not adoption. Nothing here is wired into the app. Three of the four packages are pre-1.0 and one is a single-author v0.2.0. The section that matters is Indicators: it diffs the library's ATR/RSI/EMA against ours bar for bar. A transpiled Pine indicator that is quietly wrong is the cheapest possible route to a fake edge.

Aggressor mapping

The cache stores B for a buy aggressor and A for a sell. The footprint convention is the mirror of the name — aggressive buys lift the offer and belong in askVolume, aggressive sells hit the bid and belong in bidVolume. Inverted, every imbalance on this chart would flip while still looking entirely plausible. These totals are computed in Python and re-derived from the levels in the browser; they must agree.

Why a box plot and not a mean

The vol-clock study settled that ATR sets the session clock. What a mean hides is the shape: whether the open is loud because every minute is loud, or because a handful are. The whiskers and the outlier cloud are the part worth reading — the tails are where the sub-30s trades and the stop-outs live.

Agreement with our own maths

Each row runs the library over the loaded session's bars and diffs it against a series computed in Python: ATR(14) against journal.atr.atr_series — the function the sim actually uses — and RSI(14) / EMA(20) against Wilder and standard-span references built the same way.

Read the tail column, not the first one. Every recursive indicator has to be seeded and there is no single right seed — pandas' ewm(adjust=False) starts from the first observation, Pine's ta.ema from an SMA of the first length bars — so the raw max error only ever measures that disagreement, and it is always large. What matters is whether it decays: a seed difference is multiplied by (1−α) every bar and must reach zero, so anything still standing a thousand bars later is a difference in the recursion itself. What this replaces

We have RulerPrimitive and TradeRectanglePrimitive and drawings persistence already. What this package adds is breadth — 68 tools including Fibonacci, Gann, pitchforks and position tools — behind one manager with a serialisable state, rather than one primitive per shape. The tool registry below is enumerated from the package at runtime, not hardcoded.

Everything above is generated, not written

The left rail is getToolRegistry() — tools grouped by the category each one declares, placed using its requiredAnchors and built by its own factory. No tool is named anywhere in this page. The picker is the modules that expose a metadata/calculate pair, routed to an overlay or a lower pane by metadata.overlay. Each settings dialog is rendered from that indicator's inputConfig, and the six input types below cover all of them — which is why one form renderer serves every indicator in the catalogue. Legend rows come from plotConfig, values from subscribeCrosshairMove.

Reading this page.
  • Footprint. The levels ship at the raw 0.25 increment and are re-bucketed in the browser by clusterOrderFlowBarsByMintick. That is the right split: re-bucketing a footprint is a display decision and should not cost a round trip. Our own profile primitives bucket server-side.
  • One bug found. The volume profile is drawn with createVolumeProfilePrimitive under a visible-range scope. The session scope draws nothing when the primitive is attached to the footprint custom series — true for createSessionVolumeProfilePrimitive and for createVolumeProfilePrimitive with scope: {kind:'session'}, with or without sessionId on the bars. The same call renders correctly against a standard candlestick series, so the scope resolver appears not to see a custom series' data. Worth an upstream issue; not a blocker, since visible-range is the more useful scope here anyway.
  • Vol clock. The box-whisker series is ~200 lines of plugin-example source. It has no options beyond four colours and no hit-testing, so a tooltip would be ours to write — but it puts a quartile mark on the same engine, same time axis, same crosshair as everything else.
  • Indicators. Read the agreement table before anything else. The library is fast and the plot metadata is genuinely useful, but 317 of its indicators are machine ports of community Pine and this table checks three.
  • Drawing. Interactive — nothing is persisted, and that is the point of the demo rather than a limitation of the package, which serialises drawings fine.
  • Terminal. The fifth tab is the TradingView layout — left rail, top bar, top-left legend, modal picker, generated settings — built on the same canvas. It exists to answer one question: how much of that chrome do these packages actually give you? The answer is the catalogue and its schema, which is the expensive part. It is not Advanced Charts: no symbol search, no saved layouts, no alerts, no server side. Timeframes are resampled from the shipped 1-minute bars, so 1h is a fold of 60 real bars, not a fetch.
  • Not benchmarked. Nothing here measures frame cost. The multi-chart cost model says ~65% of a core per repainting pane; a footprint series draws far more per bar than a candle and would need its own measurement before it went near a live pane.
